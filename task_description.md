# Тренажёр по рефакторингу

Скрипт [hrv_analysis.py](hrv/hrv_analysis.py) обрабатывает ряды чисел (интервалы между ударами сердца, мс) 
для нескольких испытуемых и печатает результаты. 
Разбираться в предметной области не нужно: работайте с ним как с чужим кодом, который достался вам по наследству.

## Файлы

| Файл | Что это |
|---|---|
| [hrv_analysis.py](hrv/hrv_analysis.py) | исходный скрипт |
| `data/subject_*.csv` | входные данные |
| [data/expected_output.txt](hrv/data/expected_output.txt) | эталонный вывод исходного скрипта |

## Как запускать

Все команды выполняются из корня проекта.

```bash
uv sync
uv run python hrv/hrv_analysis.py
```

Перед первым запуском создайте в корне папку `output`

## Критерии приёмки

### ✅ Обязательно

**1. Код проходит ruff проверки**

Обе команды завершаются без ошибок:

```bash
uv run ruff check .
uv run ruff format --check .
```

Правила проверки заданы в `pyproject.toml`, менять их нельзя. Отключать проверки через `# noqa` можно только с 
комментарием, объясняющим, почему вы так решили

**2. Код проходит проверку типов mypy**

Команда завершается без ошибок:

```bash
uv run mypy hrv
```

- У всех функций и методов аннотированы аргументы и возвращаемое значение.
- Одна переменная хранит значения одного типа и не используется повторно под что-то другое.
- `Any` используется только там, где тип действительно нельзя выразить.
- `# type: ignore` разрешён только с кодом ошибки и комментарием, почему иначе нельзя, например
  `# type: ignore[import-untyped]  # у библиотеки нет аннотаций`.

Настройки mypy заданы в `pyproject.toml`, ослаблять их нельзя.

**3. Соблюдаются PEP 8 и PEP 257**

- Имена переменных, функций и классов говорят, что в них лежит: никаких `x`, `data2`, `tmp`.
- Нет магических чисел: значимые константы вынесены и названы.
- Нет затенения встроенных имён (`list`, `sum`, `all` и т. п.).
- Импорты стоят в начале файла и сгруппированы.
- У каждого модуля, класса, публичной функции и метода есть docstring в формате Google. ruff
  проверяет их наличие и оформление, а вы следите, чтобы они объясняли смысл, а не пересказывали код:

  ```python
  def moving_average(values: list[float], window: int) -> list[float]:
      """Сглаживает ряд скользящим средним.

      Args:
          values: Исходный ряд.
          window: Размер окна, количество точек.

      Returns:
          Сглаженный ряд длиной len(values) - window + 1.

      Raises:
          ValueError: Если окно больше длины ряда.
      """
  ```

**4. Код разбит на функции**

- Каждая функция делает одну вещь, и её имя говорит, какую.
- Нет повторяющихся кусков кода.
- Вычисления отделены от вывода на экран и сохранения файлов.
- На верхнем уровне модуля нет логики. Точка входа выглядит так:

  ```python
  if __name__ == "__main__":
      # some logic 
  ```

**5. Есть хотя бы один класс**

Класс описывает осмысленную сущность из задачи и объединяет данные с методами, которые с ними работают. 

**6. Чистая структура репозитория**

- Код, данные и результаты лежат в отдельных папках.
- В репозитории нет мусора: `.venv/`, `__pycache__/`, `.idea/`, `output/`, 
временных и неиспользуемых файлов

**7. Красивая история коммитов**
Все изменения легко отслеживаются, у каждого коммита есть адекватное описание

## Как сдать работу

1. Сделайте **форк** этого репозитория.
2. Выполняйте работу в отдельной ветке, например `refactoring`.
3. Откройте **Merge Request** из своей ветки в `main` **своего форка**.
4. В описании MR перечислите, что сделано по каждому критерию, и отметьте выполненные дополнительные пункты.
5. Убедитесь, что преподаватель может открыть ваш MR:
   - форк **публичный** (Settings → General → Visibility → Public),
   - **или** вы выдали преподавателю доступ к проекту (Manage → Members, роль не ниже Reporter).
6. Дождитесь комментариев на сданную работу. Комментарии будут в течение недели 
7. После получения комментариев у вас есть 3 опции: 
   - Порадоваться что все гуд и курс закрыт
   - Исправить замечания (внимание, это может привести к новой пачке замечаний при следующем ревью)
   - Поспорить с комментариями в MR (сложность S, преподаватель оставляет за собой право 
     использовать скилл "Диктатура и насилие")

По всем вопросам можно спрашивать в чате
